Technical Phone Screen — 14-Day Plan

Two hours a day, building from Python fluency toward live JavaScript problem-solving across UI implementation and core data structures.
Per the official TPS guide: live coding in JavaScript/TypeScript, covering UI implementation (any framework or vanilla JS/TS), arrays/strings/objects/sets/maps, simple graph & tree traversal (BFS/DFS), recursion, sorting/filtering logic, and time/space complexity discussion.
Days 1–3 Foundation

JS syntax via porting

Rewrite problems you've already solved in Python so you're learning syntax through familiar logic, not learning both at once.
Day 1 — Arrays & Strings

Port 3–4 sliding window / two-pointer problems from Python to JS. Get comfortable with .slice(), .split(), template literals.

  • 3. Longest Substring Without Repeating Characters
  • 121. Best Time to Buy and Sell Stock
  • 11. Container With Most Water
Day 2 — Objects, Map, Set

Port hashmap-style problems (Two Sum and similar). Practice Map, Set, and plain object lookups as JS equivalents of Python dicts.

  • 1. Two Sum
  • 49. Group Anagrams
  • 242. Valid Anagram
Day 3 — Sorting & Filtering

Practice .sort() with custom comparators, .filter(), .map(), .reduce() chains. Explicitly called out in the TPS guide.

  • 238. Product of Array Except Self
  • 347. Top K Frequent Elements
Resources
  • LeetCode — switch your default language to JavaScript; re-solve problems you've already cleared in Python
  • GreatFrontEnd — JS & browser fundamentals quiz questions for quick syntax checks
  • StackBlitz — browser sandbox, zero setup, for testing snippets as you port them
  • MDN Web Docs — Array methods reference when a method name slips your mind
Days 4–6 Traversal

Trees, graphs, recursion in JS

The part most different from pure UI work, and explicitly listed in the TPS guide as its own category.
Day 4 — Recursion Basics

Factorial, Fibonacci, then simple tree problems. JS recursive syntax has small quirks (no tail-call optimization guarantee) worth a few reps.

  • 104. Maximum Depth of Binary Tree
  • 100. Same Tree
  • 226. Invert Binary Tree
Day 5 — BFS/DFS on Trees

Level order traversal, max depth, path sum — port problems you've already solved in Python.

  • 102. Binary Tree Level Order Traversal
  • 543. Diameter of Binary Tree
Day 6 — BFS/DFS on Graphs

Represent adjacency lists using Map or nested arrays. Practice queue-as-array (.push()/.shift()) and stack-as-array (.push()/.pop()) patterns.

  • 200. Number of Islands
  • 133. Clone Graph
  • 207. Course Schedule (stretch, if time allows)
Resources
  • LeetCode — Tree tag and Graph tag, filtered to Easy/Medium
  • GreatFrontEnd — coding questions for JS-flavored DSA practice
  • StackBlitz — keep building here so traversal code is testable immediately
Days 7–9 UI Implementation

Vanilla JS component builds

Layering in the UI-implementation half of the TPS guide. Vanilla JS/TS is explicitly acceptable — no need to learn Angular for this round.
Day 7 — Filterable List + Debounced Search

Build a list with a text input that filters live (case-insensitive substring match), then add a 300ms debounce so filtering only fires after the user pauses typing.

  • 20. Valid Parentheses (stack warmup before the UI build)
Day 8 — Expandable Tree View

Render a nested object (folder structure) where each node expands/collapses on click. Deliberately combines recursion with UI rendering.

Day 9 — Counter with Undo

Increment/decrement buttons plus an undo button that reverts the last action using a stack-based history array.

  • 155. Min Stack (conceptually close to this build)
  • 232. Implement Queue using Stacks
Resources
  • GreatFrontEnd — built specifically for "build a UI component" interview questions
  • JavaScript30 (free, Wes Bos) — 30 vanilla JS UI builds, no framework
  • CodeSandbox or StackBlitz — live sandbox closest to a real interview coding environment
Days 10–11 Communication

Time & space complexity drilling

Explicitly its own bullet in the TPS guide — they'll expect you to state Big-O out loud, not just write working code.
Day 10 — Narrate Days 1–6 Solutions

Go back through your DSA solutions and say the complexity out loud for each, including tradeoffs ("O(n) time, O(n) space with a hashmap, versus O(n²) brute force with no extra space").

Day 11 — Narrate Days 7–9 Solutions

Same exercise for the UI builds — state the complexity of your filtering logic, debounce, and recursive tree rendering.

Resources
  • Big-O Cheat Sheet — quick reference while narrating
  • No new problems here — the resource is repetition, out loud, on what you've already built
Days 12–13 Simulation

Timed mocks

Closest rehearsal to the actual call: one DSA problem and one UI build per day, under time pressure, narrating the whole way through.
Day 12 — Mock 1

One DSA problem (30–40 min) + one UI build (30–40 min), picked cold, no looking up syntax mid-problem.

  • 56. Merge Intervals
  • 73. Set Matrix Zeroes
Day 13 — Mock 2

Repeat with fresh problems. If a recruiter has shared their coding environment (CoderPad, CodeSandbox, shared doc), mock inside that same tool.

  • 211. Design Add and Search Words Data Structure
  • 295. Find Median from Data Stream (harder, only if Days 1–11 felt comfortable)
Resources
  • LeetCode — pick random Easy/Medium problems untagged, to simulate not knowing what's coming
  • GreatFrontEnd — pull a UI question you haven't seen yet
  • Whatever environment the recruiter confirms they'll use for the actual round
Day 14 Buffer

Light review & rest

Revisit anything that felt shaky during the mocks. If the call is scheduled close to this window, treat this as a rest day, not a cram day.
Before the call

Confirm with the recruiter

Ask directly: which round tests UI-building vs. DSA-in-JS (or both, per the guide), what coding environment they use (CoderPad, CodeSandbox, shared doc), and whether vanilla JS is genuinely fine or if they lean toward seeing a framework.
